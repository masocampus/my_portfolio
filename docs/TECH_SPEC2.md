# 개인 포트폴리오 기술 명세

`docs/PRD.md`의 단일 페이지 요구를 구현 순서로 나눈 문서다. `docs/TECH_SPEC.md`의 여덟 단계를 세 단계로 통합했다. 화면 요구의 기준은 PRD이며, 이 문서는 그 요구를 어떤 순서로 코드에 옮길지만 다룬다.

## 현재 기준선

앱 코드는 `src/app` 네 파일뿐이다. 포트폴리오 섹션, shadcn/ui, 샘플 콘텐츠 모듈은 없다.

| 파일 | 상태 |
| --- | --- |
| `src/app/layout.tsx` | Geist Sans / Geist Mono 연결. `lang="en"`. 제목은 "Create Next App" |
| `src/app/page.tsx` | Next.js 시작 화면. 로고, 안내 문구, 외부 링크 |
| `src/app/globals.css` | Tailwind CSS v4. 시스템 다크 모드가 색을 바꿈. 본문 서체는 Arial |
| `public/` | `next.svg`, `vercel.svg` 등 템플릿 아이콘 |

스택은 Next.js 16.3.8, React 19, TypeScript strict, Tailwind CSS v4, `@/*` 경로 별칭이다. `components.json`과 `src/components`는 없다. 라우트는 `/`와 기본 not-found뿐이다.

PRD와 바로 맞출 항목은 다음이다.

- 다크 모드 미디어 쿼리 제거. 라이트 단일 테마만 유지한다.
- 본문 서체를 Geist Sans로 맞춘다. Arial을 쓰지 않는다.
- 문서 언어와 메타데이터를 한국어 샘플로 바꾼다.

범위 밖은 다크 모드 전환, 언어 전환, CMS, 블로그, 실제 문의 전송, 애니메이션 라이브러리, 프로젝트 상세 페이지, 분석 도구다. Sonner는 Contact가 전송 결과를 알리지 않으므로 추가하지 않는다.

## 개발 구현 명세

기존 여덟 단계를 의존 순서대로 세 단계로 묶는다. 토큰과 데이터를 먼저 고정하고, 그 위에 페이지 골격과 이동을 올린 뒤, 섹션 내용과 수용 기준을 한 번에 맞춘다.

| 통합 단계 | 담는 기존 단계 | 끝나는 상태 |
| --- | --- | --- |
| 1단계. 기반과 콘텐츠 | 기반 정리, 샘플 콘텐츠 | 테마와 shadcn, 한곳의 샘플 데이터가 준비된다 |
| 2단계. 골격과 이동 | 페이지 골격, Header와 스크롤 | 빈 섹션이 순서대로 있고, 메뉴로 이동할 수 있다 |
| 3단계. 섹션과 확인 | Hero, About, Skills, Projects, Experience, Contact, Footer, 수용 기준 | 명세 화면이 채워지고 확인을 마친다 |

### 1단계. 기반과 콘텐츠

테마, UI 부품, 문서 메타, 샘플 문구를 화면보다 먼저 고정한다.

- 설치된 Next.js 문서(`node_modules/next/dist/docs/`)를 확인한 뒤 shadcn/ui를 CLI로 초기화한다.
- 명세에 있는 Button, Badge, Card, Separator, Sheet, Input, Textarea, Label만 추가한다. 컴포넌트는 `@/components/ui/*`에서 가져온다.
- `src/app/globals.css`의 `@theme`에 아래 색만 둔다. `tailwind.config.js`는 만들지 않는다.

| 역할 | 값 | 쓰는 곳 |
| --- | --- | --- |
| 캔버스 | `#F7F6F3` | 페이지 배경 |
| 면 | `#FFFFFF` | 헤더, 카드 |
| 잉크 | `#1A1A1A` | 제목, 본문 |
| 보조 | `#5C5A56` | 부제, 메타, 라벨 |
| 선 | `#E6E4DF` | 구분선, 카드 테두리, 입력 테두리 |
| 포인트 | `#1F3A5F` | 링크, 현재 메뉴, 포커스, 주요 버튼 |

- 포인트색은 링크, 현재 메뉴, 포커스, 주요 버튼에만 쓴다. 배경 전체를 포인트색으로 칠하지 않는다.
- 다크 모드 분기를 제거한다. 시스템 색 설정에 따라 색이 바뀌지 않아야 한다.
- 본문 서체를 Geist Sans로 맞춘다.
- `layout.tsx`의 `lang`을 `ko`로 두고, 문서 제목과 설명을 한국어 샘플로 바꾼다.
- `src/data/portfolio.ts`에 Hero, About, Skills, Projects, Experience, Contact 안내, Footer 문구를 둔다.
- PRD 8장의 자리표시자를 기본값으로 둔다. 실명과 실경력으로 바꿀 때는 이 파일만 수정한다.
- 프로젝트는 URL이 있는 항목과 없는 항목을 타입으로 구분한다. 썸네일 필드는 선택 값으로 두고, 없을 때는 이미지 영역을 렌더하지 않는다.
- 경력 배열은 최신순을 유지한다.

기본 카피는 다음을 포함한다.

- Hero eyebrow: Product Designer
- Hero 제목: 김서연
- Hero 부제: 복잡한 서비스를 읽기 쉬운 화면으로 정리합니다.
- About 역할: 프로덕트 디자인 · 8년
- Skills 카테고리: Product, Interface, Collaboration
- Projects 3건. 첫 카드만 예시 URL, 나머지는 링크 없음
- Experience 3건. 최신 항목이 위
- Contact 안내: 이 양식은 화면 예시입니다. 입력 내용은 전송되지 않습니다.

### 2단계. 골격과 이동

데이터는 아직 카드와 문단으로 풀지 않고, 섹션 자리와 이동만 먼저 동작하게 한다.

- `/` 한 페이지에 Header, Hero, About, Skills, Projects, Experience, Contact, Footer 순서를 고정한다.
- 섹션 id는 `hero`, `about`, `skills`, `projects`, `experience`, `contact`이다.
- `h1`은 Hero에만 두고, 섹션 제목은 `h2`로 둔다.
- 모바일 우선으로 맞춘다.

| 항목 | 값 |
| --- | --- |
| 본문 최대 폭 | 1152px, 가운데 정렬 |
| 좌우 패딩 | 좁은 화면 24px, 넓은 화면 32px |
| 헤더 높이 | 64px, 상단 고정. 캔버스색에 가까운 반투명 면 |
| 섹션 세로 패딩 | 모바일 80px, 데스크톱 112px |
| Projects 열 | 모바일 1열, 768px 이상 2열, 1024px 이상 3열 |
| Skills 열 | 모바일 1열, 768px 이상 2열 |

- 앵커 도착 위치가 고정 헤더에 가리지 않도록 스크롤 여백을 헤더 높이만큼 둔다.
- 섹션은 면의 밝기 차이와 옅은 구분선으로만 나눈다. 그라데이션, 패턴, 풀블리드 사진은 쓰지 않는다.
- 왼쪽 이름 텍스트 로고를 클릭하면 페이지 상단으로 이동한다.
- 메뉴는 About, Skills, Projects, Experience, Contact이다.
- 데스크톱 메뉴 클릭 시 해당 섹션으로 스크롤한다.
- 768px 미만에서는 햄버거 버튼으로 Sheet를 연다. 항목을 고르면 Sheet가 닫히고 해당 섹션으로 이동한다.
- 스크롤 위치에 따라 현재 섹션 메뉴 하나만 포인트색으로 표시한다.
- `prefers-reduced-motion: reduce`이면 즉시 이동한다. 그 외에는 짧은 스크롤만 사용한다.
- 키보드로 메뉴와 Sheet를 열고 닫을 수 있게 한다. 포커스 링은 포인트색으로 보이게 한다.
- 호버 피드백은 색과 밑줄만 사용한다. 큰 이동, 확대, 패럴랙스는 쓰지 않는다.

### 3단계. 섹션과 확인

1단계 데이터와 2단계 골격을 이어서 Hero부터 Footer까지 채우고, 수용 기준을 확인한다.

**Hero와 About**

- Hero는 eyebrow 한 줄, 이름 또는 한 문장 제목, 부제 두 줄 이내, 버튼 두 개만 둔다.
- 주요 버튼은 Projects로, 보조 버튼은 Contact로 이동한다.
- Hero와 About에 초상, 일러스트, 배경 장식을 두지 않는다.
- About은 섹션 라벨, 제목, 본문 2–3문단, 역할 한 줄을 둔다.

타이포그래피는 다음을 따른다. 한 화면의 굵기 단계는 본문과 제목 두 단계를 넘기지 않는다.

| 역할 | 크기 | 굵기 | 자간·행간 |
| --- | --- | --- | --- |
| Hero 제목 | 모바일 40px, 데스크톱 64px | 500–600 | 자간 타이트, 행간 1.1 |
| 섹션 제목 | 모바일 28px, 데스크톱 36px | 500 | 자간 약간 타이트 |
| 본문 | 16–18px | 400 | 행간 1.7 |
| 라벨·메타 | 12–13px | 500 | 자간 넓게, 보조색 |

**Skills, Projects, Experience**

- Skills는 카테고리 3개 내외다. 각 카테고리는 제목과 Badge 목록이다. 숙련도 바, 퍼센트, 차트는 만들지 않는다.
- Projects는 샘플 3건이다. 카드에 제목, 한 줄 설명, 태그, 기간 또는 역할을 넣는다.
- 외부 URL이 있으면 카드 또는 텍스트 링크로 새 탭에서 연다. URL이 없으면 링크를 만들지 않는다. 상세 페이지는 없다.
- 썸네일은 에셋이 있을 때만 카드당 1장이다. 없으면 제목, 한 줄 설명, 태그로만 구성하고 빈 이미지 영역을 두지 않는다.
- Experience는 최신순 세로 목록이다. 항목마다 기간, 조직, 역할, 요약 두 줄 이내를 둔다.
- 타임라인 점과 선은 구분선 색의 가는 선까지만 허용한다.

**Contact와 Footer**

- Contact는 화면 목업이다. 필드와 버튼은 보이기만 한다.
- 필드는 이름, 이메일, 메시지다. 라벨과 빈 입력 영역, 보내기 버튼이 보인다.
- 보내기 버튼은 `type="button"`으로 둔다. 제출, 검증, 메일 앱 연결, 서버 전송, 저장, 토스트를 연결하지 않는다.
- 필드 아래에 안내 한 줄을 둔다. 문구는 "이 양식은 화면 예시입니다. 입력 내용은 전송되지 않습니다."
- Footer에는 이름, 한 줄 소개, 저작 표기, 상단으로 이동하는 텍스트 링크 하나를 둔다.
- 이미지는 파비콘 1종과, 에셋이 있을 때의 프로젝트 썸네일만 허용한다.

**확인**

아래를 확인한 뒤 `npm run lint`를 통과시킨다.

- `/` 한 페이지에서 여섯 섹션과 헤더, 푸터가 PRD 순서로 보인다.
- 데스크톱 메뉴와 모바일 Sheet 모두 해당 섹션으로 이동하고, 제목이 헤더에 가리지 않는다.
- 스크롤 중 현재 섹션 메뉴가 하나만 표시된다.
- 캔버스, 잉크, 포인트색이 역할대로 쓰이고, 다크 모드로 전환되지 않는다.
- Hero와 About에 인물 사진과 장식 이미지가 없다.
- 썸네일 없는 프로젝트 카드에 빈 이미지 칸이 없다.
- Contact 보내기 버튼이 네트워크 요청, 메일 앱, 저장을 일으키지 않는다.
- 키보드만으로 메뉴, Sheet, 본문 링크에 도달하고 포커스가 보인다.
- 데스크톱과 모바일 폭에서 열 구성, 패딩, 헤더 Sheet 전환을 확인한다.

## 고려 사항

샘플 문장을 실명과 실경력으로 바꿔도 레이아웃이 유지되려면 제목과 본문 길이는 데이터에서만 바꾸고, 섹션 컴포넌트는 고정 높이를 갖지 않는다. 프로젝트 카드가 3개를 넘으면 그리드만 늘리고, 경력 목록이 길어지면 세로 스택만 늘린다. 현재 섹션 감지는 스크롤 처리 한곳에 두고, 섹션 수는 여섯이라 별도 가상화는 두지 않는다.
