# 개인 포트폴리오 1페이지 기능 명세서

## 1. 개요

모던하고 전문적으로 보이는 개인 포트폴리오를 **단일 페이지**로 만든다. 인상은 사진이 아니라 **레이아웃, 배경색, 타이포그래피**로 만든다.

| 항목 | 내용 |
| --- | --- |
| 라우트 | `/` 하나 |
| 카피 | 한국어. 이름·직무·기술명은 영문 병기 가능 |
| 데이터 | 코드에 두는 정적 샘플. CMS 없음 |
| 테마 | 단일 라이트. 시스템 다크 모드에 따라 색이 바뀌지 않음 |

샘플 문구는 교체용이다. 실명·실경력으로 바꿔도 레이아웃이 깨지지 않아야 한다.

## 2. 정보 구조

페이지는 위에서 아래로 한 번만 흐른다.

1. Header — 고정 내비게이션
2. Hero
3. About
4. Skills
5. Projects
6. Experience
7. Contact — 화면 목업
8. Footer

각 섹션은 앵커를 가진다. `hero`, `about`, `skills`, `projects`, `experience`, `contact`.

## 3. 기술 제약

- UI는 shadcn/ui. 컴포넌트는 CLI로 추가하고 `@/components/ui/*`에서 가져온다.
- 스타일은 Tailwind CSS v4. 전역 스타일은 `src/app/globals.css`의 `@import "tailwindcss"`와 `@theme`로만 조정한다. `tailwind.config.js`는 만들지 않는다.
- 현재 앱은 Next.js 기본 템플릿이며 shadcn/ui는 아직 없다. 이 명세는 화면 요구만 다룬다.

## 4. 비주얼

### 4.1 배경과 색

따뜻한 종이색 캔버스 위에 흰색 면을 올린다. 섹션은 면의 밝기 차이와 옅은 구분선으로만 나눈다. 그라데이션, 패턴, 풀블리드 사진은 쓰지 않는다.

| 역할 | 값 | 쓰는 곳 |
| --- | --- | --- |
| 캔버스 | `#F7F6F3` | 페이지 배경 |
| 면 | `#FFFFFF` | 헤더, 카드 |
| 잉크 | `#1A1A1A` | 제목, 본문 |
| 보조 | `#5C5A56` | 부제, 메타, 라벨 |
| 선 | `#E6E4DF` | 구분선, 카드 테두리, 입력 테두리 |
| 포인트 | `#1F3A5F` | 링크, 현재 메뉴, 포커스, 주요 버튼 |

포인트색은 위 네 곳에만 쓴다. 배경 전체를 포인트색으로 칠하지 않는다.

### 4.2 타이포그래피

UI 서체는 기존 Geist Sans를 유지한다. 본문 대체 서체로 Arial을 쓰지 않는다.

| 역할 | 크기 | 굵기 | 자간·행간 |
| --- | --- | --- | --- |
| Hero 제목 | 모바일 40px, 데스크톱 64px | 500–600 | 자간 타이트, 행간 1.1 |
| 섹션 제목 | 모바일 28px, 데스크톱 36px | 500 | 자간 약간 타이트 |
| 본문 | 16–18px | 400 | 행간 1.7 |
| 라벨·메타 | 12–13px | 500 | 자간 넓게, 보조색 |

한 화면에 굵기 단계는 두 단계(본문, 제목)를 넘기지 않는다.

### 4.3 레이아웃

- 모바일 우선. 좌우 패딩은 좁은 화면 24px, 넓은 화면 32px.
- 본문 최대 폭 1152px, 가운데 정렬.
- 헤더 높이 64px, 상단 고정. 배경은 캔버스색에 가까운 반투명 면.
- 섹션 세로 패딩은 모바일 80px, 데스크톱 112px.
- Projects는 모바일 1열, 768px 이상 2열, 1024px 이상 3열.
- Skills 묶음은 모바일 1열, 768px 이상 2열.

### 4.4 이미지

초상, 히어로 비주얼, 장식 일러스트, 스톡 이미지는 사용하지 않는다.

허용 범위는 다음뿐이다.

- 파비콘 1종
- 프로젝트 카드 썸네일. 에셋이 있을 때만 카드당 1장. 없으면 제목, 한 줄 설명, 태그로만 구성하고 빈 이미지 영역을 두지 않는다

## 5. 섹션별 요구

### 5.1 Header

- 왼쪽은 이름 텍스트 로고. 클릭하면 페이지 상단으로 이동한다.
- 메뉴: About, Skills, Projects, Experience, Contact.
- 메뉴 클릭 시 해당 섹션으로 스크롤한다. 도착 위치는 고정 헤더에 가리지 않도록 헤더 높이만큼 위를 비운다.
- 스크롤 위치에 따라 현재 섹션 메뉴만 포인트색으로 표시한다.
- 768px 미만에서는 햄버거 버튼으로 Sheet를 연다. 항목을 고르면 Sheet가 닫히고 해당 섹션으로 이동한다.
- 키보드로 메뉴와 Sheet를 열고 닫을 수 있다.

### 5.2 Hero

- eyebrow 한 줄(직무), 이름 또는 한 문장 제목, 부제 두 줄 이내.
- 버튼 두 개: 주요 버튼은 Projects로 이동, 보조 버튼은 Contact로 이동.
- 사진, 일러스트, 배경 장식 없음.

### 5.3 About

- 섹션 라벨, 제목, 본문 2–3문단, 역할 한 줄.
- 사진 자리 없음.

### 5.4 Skills

- 카테고리 3개 내외. 각 카테고리는 제목과 Badge 목록.
- 숙련도 바, 퍼센트, 차트 없음.

### 5.5 Projects

- 샘플 3건. 카드에 제목, 한 줄 설명, 태그, 기간 또는 역할을 넣는다.
- 외부 URL이 있으면 카드 또는 텍스트 링크로 새 탭에서 연다. URL이 없으면 링크를 만들지 않는다.
- 상세 페이지 없음.

### 5.6 Experience

- 최신순 세로 목록. 항목마다 기간, 조직, 역할, 요약 두 줄 이내.
- 타임라인 점·선은 구분선 색의 가는 선까지만 허용한다.

### 5.7 Contact

화면 목업이다. 입력은 보여 주기만 한다.

- 필드: 이름, 이메일, 메시지
- 라벨과 빈 입력 영역, 보내기 버튼이 보인다
- 버튼은 제출되지 않는다. 검증, 메일 앱 연결, 서버 전송, 저장, 토스트는 하지 않는다
- 필드 아래에 짧은 안내 한 줄: 화면 예시이며 전송되지 않는다는 뜻의 한국어 문구

### 5.8 Footer

- 이름, 한 줄 소개, 저작 표기.
- 상단으로 이동하는 텍스트 링크 하나.

## 6. 공통 동작

- 제목 단계는 페이지에 `h1` 하나(Hero), 섹션은 `h2`.
- 포커스 링은 포인트색으로 분명히 보이게 한다.
- `prefers-reduced-motion: reduce`이면 스크롤 이동을 즉시 점프로 한다. 그 외에는 짧은 스크롤만 허용한다.
- 호버 피드백은 색과 밑줄 정도만. 큰 이동, 확대, 패럴랙스는 쓰지 않는다.
- 문서 제목과 설명 메타는 한국어 샘플로 둔다.

## 7. UI 부품

shadcn/ui만 사용한다. 이 화면에서 필요한 부품은 다음이다.

- Button, Badge, Card, Separator, Sheet, Input, Textarea, Label

Sonner는 쓰지 않는다. Contact가 전송 결과를 알리지 않기 때문이다.

## 8. 샘플 콘텐츠

아래는 자리표시자다. 구현 시 이 문구를 기본값으로 두고, 한곳에서 교체할 수 있게 둔다.

**Hero**

- eyebrow: Product Designer
- 제목: 김서연
- 부제: 복잡한 서비스를 읽기 쉬운 화면으로 정리합니다.

**About**

- 본문 요지: 문제 정의, 정보 구조, 화면 설계를 한 흐름으로 맡는다는 2–3문단
- 역할 한 줄: 프로덕트 디자인 · 8년

**Skills 카테고리 예**

- Product: 정보 구조, 사용자 흐름, 프로토타입
- Interface: 타이포그래피, 디자인 시스템, 접근성
- Collaboration: 워크숍 퍼실리테이션, 명세 작성, 개발 협업

**Projects 3건**

- 각 항목: 한글 제목, 한 줄 설명, 태그 2–3개. 링크는 첫 번째 카드만 예시 URL, 나머지는 링크 없음

**Experience 3건**

- 각 항목: 기간, 조직명, 역할, 요약 한두 문장. 최신 항목이 위

**Contact 안내 문구**

- 이 양식은 화면 예시입니다. 입력 내용은 전송되지 않습니다.

## 9. 수용 기준

- `/` 한 페이지에서 여섯 섹션과 헤더·푸터가 위 순서로 보인다.
- 데스크톱 메뉴와 모바일 Sheet 모두 해당 섹션으로 이동하고, 제목이 헤더에 가리지 않는다.
- 스크롤 중 현재 섹션 메뉴가 하나 표시된다.
- 캔버스, 잉크, 포인트색이 4.1의 역할대로 쓰이고, 다크 모드로 전환되지 않는다.
- Hero와 About에 인물·장식 이미지가 없다.
- 썸네일 없는 프로젝트 카드에 빈 이미지 칸이 없다.
- Contact 보내기 버튼이 네트워크 요청, 메일 앱, 저장을 일으키지 않는다.
- 키보드만으로 메뉴, Sheet, 본문 링크에 도달하고 포커스가 보인다.

## 10. 범위 밖

다크 모드 전환, 언어 전환, CMS, 블로그, 실제 문의 전송, 애니메이션 라이브러리, 프로젝트 상세 페이지, 분석 도구.
